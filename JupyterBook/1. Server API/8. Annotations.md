# Annotations

(annotation-object)=
## Annotation object

Each annotation returned from the API is a JSON object with the following properties:

- `id`: (read only) The ID of the annotation.
- `annotation_type_id`: The ID of the type of the annotation.
- `type`: (read only) The annotation type (template) object that this annotation is based on. Embeds the same fields the type object returns from `GET /annotation-template/types/{id}` — at minimum `id`, `name`, and `extended_data`. Maps to `annotation_type_id`.
- `annotation_set_id`: The ID of the annotation set which the annotation belongs to.
- `image_id`: The ID of the image which the annotation belongs to. Only applies to annoations from image annotation sets.
- `target`: the Web Annotation target. See [Annotation target](annotation-target) for details.
- `line_color`: The HEX color code used for outline color of the annotation. E.g. `#000000`.
- `line_weight`: The outline color shade of the annotation. The value should be one of the values of `light`, `medium`, and `dark`.
- `fields`: the field data of the annotation. See [Annotation fields](annotation-fields) for details.
- `tags`: list of tags applied to the annotation. See [Annotation Tags](annotation-tags) for details.
- `weight`: (read only) The integer used to order the annotation within its annotation set. A `null` value indicates the annotation has not been explicitly ordered. See [Reorder annotations](#reorder-annotations) for how this value is set.
- `created_at`: (read only) The datetime when the annotation is created.
- `updated_at`: (read only) The datetime when the annotation is updated.

(annotation-target)=
## Annotation target

The REST and IIIF annotation write endpoints accept a single target in any of the forms below. Targets are
validated and normalized to a source-based `SpecificResource` object before saving. This API supports the
[Web Annotation target model](https://www.w3.org/TR/annotation-model/#specific-resources) with the restrictions
described here.

### Whole-image annotations

To annotate an entire image, identify its Canvas and omit `selector`. A full-image rectangle is unnecessary.
The target itself is still required; `target: null` and `selector: null` are invalid.

The following are equivalent whole-Canvas target inputs. Each example is the value of the annotation's `target`
property, not a complete request:

URI string:

```json
"https://glycerine.example/api/iiif/canvas/42"
```

Identified resource object:

```json
{
    "id": "https://glycerine.example/api/iiif/canvas/42",
    "type": "Canvas"
}
```

Source-based target:

```json
{
    "type": "SpecificResource",
    "source": "https://glycerine.example/api/iiif/canvas/42"
}
```

Target with an identified source object:

```json
{
    "type": "SpecificResource",
    "source": {
        "id": "https://glycerine.example/api/iiif/canvas/42",
        "type": "Canvas"
    }
}
```

The URLs and IDs in these examples are illustrative. For an image hosted by Glycerine, use the actual Canvas
URI returned by the server.

For source-based targets, `type` may be omitted; if supplied, it must be `SpecificResource`. Its own optional
`id` identifies the specific resource, while `source` identifies the resource being annotated. An
`id` on a `SpecificResource` does not replace its required `source`.

### Normalized target representation

A URI string is saved as:

```json
{
    "source": "https://glycerine.example/api/iiif/canvas/42",
    "type": "SpecificResource"
}
```

An identified resource object is wrapped as the `source` of a `SpecificResource`. An existing identified source
object is retained, including its metadata. Consequently, the normalized `source` may be a URI string or an
object with an `id`; clients should not assume it is always a string. Compatible target properties such as
`styleClass` and selectors are preserved during normalization.

When `image_id` is available, IIIF representations use that image's Canvas URI as `target.source`; publication
representations continue to use their applicable public Canvas URI. The image association is authoritative
even if the submitted source differs.

### Region annotations

Use a source-based target with a selector to annotate a region. For example:

```json
{
    "type": "SpecificResource",
    "source": "https://glycerine.example/api/iiif/canvas/42",
    "selector": {
        "type": "SvgSelector",
        "value": "<svg><polygon points=\"10,10 100,10 100,100 10,100\"></polygon></svg>"
    }
}
```

The supported selector types are:

- `FragmentSelector`: requires a nonempty string `value`, for example `xywh=pixel:10,20,100,200`.
- `SvgSelector`: requires a nonempty inline string `value` or an absolute HTTP(S) `id` identifying the SVG.

Selector validation checks this structure; it does not perform full SVG or Web Annotation validation. Other
selector types, empty or null selectors, and selector arrays are rejected. Put selectors on a source-based
target rather than directly on an identified resource object.

A rectangular fragment on a target URI is also accepted, for example:

```json
"https://glycerine.example/api/iiif/canvas/42#xywh=10,20,100,200"
```

Before saving, the fragment is removed from the source URI and becomes:

```json
{
    "source": "https://glycerine.example/api/iiif/canvas/42",
    "type": "SpecificResource",
    "selector": {
        "type": "FragmentSelector",
        "value": "xywh=10,20,100,200",
        "conformsTo": "http://www.w3.org/TR/media-frags/"
    }
}
```

URI rectangle fragments accept default units, `pixel:`, or `percent:`. Coordinates must be nonnegative and
width and height must be positive. Percentage rectangles must fit within 100 percent in each dimension.
Other URI fragments, including `#t=...`, are rejected. A URI fragment and an explicit selector cannot be supplied
together. A URI containing `#xywh=...` still describes a region even though the input has no `selector` property.
IIIF output removes the `pixel:` prefix from FragmentSelector values.

To replace a region with a whole-image target, submit a replacement source-based target without a selector or
URI fragment.

### Target validation errors

The resource URI must be a nonempty absolute HTTP(S) URI. Missing required targets, empty objects, relative or
non-HTTP(S) URIs, scalar values other than URI strings, target arrays, and malformed selectors are rejected.
Invalid targets are rejected before the annotation, its fields, or its tags are changed.

REST create/update requests return HTTP `422` with an `errors.target` entry for target validation failures.
IIIF create/update requests return HTTP `400` with a `message` instead.

(annotation-fields)=
## Annotation fields

The `fields` property of an annotation is an array of objects containing the following properties:

- `field`: The field information of the value. It can be the field ID or an object with the basic field information:
  - `id`: The ID of the field.
  - `name`: The name of the field.
  - `type`: The type of the field. The value should be one of the following: `text`, `long_text`, `link`, `choice`, `date`.
- `values`: The values of the field. It is an object where each key is a language code and the value is an
array of field values in that language. Each item of the array is a string value, except for the link field
where each item is an object with the `url` and `text` properties.

Example of a `text` field:

```json
{
    "field": {
        "id": 1,
        "name": "Title",
        "type": "text"
    },
    "values": {
        "en": [
            "Title in English"
        ],
        "zh": [
            "中文标题"
        ]
    }
}
```

Example of a `link` field:

```json
{
    "field": {
        "id": 2,
        "name": "Link",
        "type": "link"
    },
    "values": {
        "en": [
            {
                "url": "https://example.com",
                "text": "Link 1"
            },
            {
                "url": "https://example.com",
                "text": "Link 2"
            }
        ],
        "zh": [
            {
                "url": "https://example.com",
                "text": "链接 1"
            },
            {
                "url": "https://example.com",
                "text": "链接 2"
            }
        ]
    }
}
```

(annotation-tags)=
## Annotation Tags

The `tags` property of an annotation is an array of objects containing the following properties:

- `term_label`: (required) The label of the tagging term.
- `term_id`: The ID of the tagging term.
- `vocabulary_id`: The ID of the vocabulary which the tag belongs to.
- `vocabulary_name`: The name of the vocabulary which the tag belongs to.
- `extended_data`: An object containing additional data of the tagging term such as the description and hierarchy 
information of the term. For example:

```json
{
    "description": "This group covers civil engineering.",
    "trace": [
        {
            "key": "https://linked.data.gov.au/def/anzsrc-for/2020/40",
            "label":"ENGINEERING"
        }
    ]
}
```

## Get all annotations

```
GET /annotation-sets/{annotation_set_id}/annotations
```

Get all annotations in an annotation set.

### URL parameters

- `annotation_set_id`: The ID of the annotation set.

### Response

An array of annotation objects.

## Create an annotation

```
POST /annotation-sets/{annotation_set_id}/annotations
```

Create an annotation in an annotation set.

### URL parameters

- `annotation_set_id`: The ID of the annotation set.

### Request

The request body should be an annotation object used to create a new annotation. Read only properties will be ignored.

- `annotation_type_id`: (required) Integer ID of the annotation template.
- `target`: (required) One of the [supported target inputs](#annotation-target), with or without a selector.
- `image_id`: Optional integer image association. REST creation uses this explicit value; it does not infer an
  image ID from the target URI. Omit it for a target without a local image association.

Example of a whole-image annotation (using illustrative IDs):

```json
{
    "annotation_type_id": 1,
    "image_id": 42,
    "target": {
        "type": "SpecificResource",
        "source": "https://glycerine.example/api/iiif/canvas/42"
    }
}
```

A missing or invalid target returns HTTP `422` before creation.

### Response

HTTP `200` with the annotation object of the newly created annotation, including its normalized target.

## Get an annotation

```
GET /annotation-sets/{annotation_set_id}/annotations/{id}
```

Get an annotation by its ID.

### URL parameters

- `annotation_set_id`: The ID of the annotation set.
- `id`: The ID of the annotation.

### Response

The annotation object of the queried annotation.

## Update an annotation

```
PUT /annotation-sets/{annotation_set_id}/annotations/{id}
```

Update an annotation by its ID.

### URL parameters

- `annotation_set_id`: The ID of the annotation set.
- `id`: The ID of the annotation.

### Request

The request body should be an annotation object used to update the annotation. Read only properties will be ignored.

If `target` is supplied, it must be a valid [supported target input](#annotation-target) and is normalized before
saving. If omitted, the existing target is unchanged. An explicit `null` target is invalid and returns HTTP `422`.

Updating `target` does not change or infer `image_id`. Submitting `image_id` to this REST update endpoint does not
reassign the annotation to another image.

### Response

HTTP `200` with the annotation object after the update.

## Delete an annotation

```
DELETE /annotation-sets/{annotation_set_id}/annotations/{id}
```

Delete an annotation by its ID.

### URL parameters

- `annotation_set_id`: The ID of the annotation set.
- `id`: The ID of the annotation.

### Response

The annotation object of the deleted annotation.

(reorder-annotations)=
## Reorder annotations

```
POST /annotation-sets/{annotation_set_id}/annotations/reorder
```

Set the display order of annotations within an annotation set. The endpoint accepts an ordered array of annotation IDs and assigns each listed annotation a `weight` equal to its position in the array (starting from `0`).

The list may be partial. Listed annotations receive the new `weight` values, while annotations not included in the request keep their existing `weight` (which may be `null` if they have never been ordered). Annotations with an explicit `weight` are returned before those without; ties and unordered annotations are sorted by their `id` in ascending order.

### URL parameters

- `annotation_set_id`: The ID of the annotation set.

### Request

The request body should be a JSON object with the following property:

- `annotation_ids`: (required) An ordered array of annotation IDs. All IDs must belong to the target annotation set. Duplicate IDs are not allowed. An empty array is accepted and is treated as a no-op.

Example:

```json
{
    "annotation_ids": [12, 7, 19]
}
```

### Response

An array of annotation objects of the annotation set in the resulting display order, including the updated `weight` values.
