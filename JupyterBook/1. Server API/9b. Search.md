# Search

## Search within a collection

```
GET /collections/{collection_id}/search
```

This will search entities from a given collection based on the query parameters from the request URL. The `type`
parameter specifies the type of the entity to search. If multiple values are needed to pass to the same parameter,
concatenate them with a comma or use the array notation. For example, to specify multiple image IDs to search.

Comma separated:

```
GET /collections/{collection_id}/search?type=image&id=1,2,3
```

Array notation, which is useful when values contain commas:

```
GET /collections/{collection_id}/search?type=image&id[]=1&id[]=2&id[]=3
```

The following are a list of supported types:

- `annotation`
- `image`
- `image_set`
- `annotation_set`
- `tag`: The tags applied to the annotations in the collection.

The following lists the supported query parameters.

- `id`: Used for searching entities by ID. Multiple values are supported.
- `full_text`: Used for full text search.
- `tag_label`: Used for searching entities by tag label. Multiple values are supported.
- `page`: (optional) The page number to return. Must be an integer greater than or equal to `1`. Defaults to `1`
  when pagination is enabled.
- `per_page`: (optional) The number of results per page. Must be an integer between `1` and `100`. Defaults to `20`
  when pagination is enabled.

The following table lists the supported query parameters for each type.

| Type               | `id` | `full_text` | `tag_label` |
|--------------------|------|-------------|-------------|
| `annotation`       | ✓    | ✓           | ✓           |
| `image`            | ✓    |             |             |
| `image_set`        | ✓    |             |             |
| `annotation_set`   | ✓    |             |             |
| `tag`              |      | ✓           |             |

### Response

The response format depends on whether `page` or `per_page` is present in the request.

#### Without pagination

When neither `page` nor `per_page` is provided, the response remains an array of all matching entities, or an empty
array if no entities are found.

#### With pagination

Providing either `page` or `per_page` enables pagination for all supported search types: `annotation`, `image`,
`image_set`, `annotation_set`, and `tag`. These parameters can be combined with the search filters supported by each
type in the table above. Results are ordered by ascending entity ID.

For example, to return the second page with 10 images per page:

```
GET /collections/{collection_id}/search?type=image&per_page=10&page=2
```

Providing only `page=2` returns the second page with the default 20 results per page. Providing only `per_page=10`
returns the first page with 10 results per page.

The response is a paginated result object, using the same format as [Search image sets by name](search-image-sets),
with the following properties:

- `data`: An array of matching entities on the current page. Each entity retains the same fields as in the
  unpaginated response.
- `current_page`: The current page number.
- `per_page`: The number of results per page.
- `total`: The total number of matching entities across all pages.
- `last_page`: The last page number.
- `from`: The position of the first result on the current page, or `null` if the page is empty.
- `to`: The position of the last result on the current page, or `null` if the page is empty.
- `first_page_url`, `last_page_url`, `prev_page_url`, `next_page_url`: The URLs of the corresponding pages.
  `prev_page_url` and `next_page_url` are `null` when there is no such page. Pagination URLs retain the search query
  parameters, including the search type and filters.
- `links`: An array of pagination links, each with `url`, `label` and `active` properties.
- `path`: The base URL of the endpoint.

If no entities match, or the requested page is beyond the last page, `data` is an empty array. The `total` still
reflects the total number of matches. For `tag` searches, tags are deduplicated by `term_id` before pagination and
counting. The matching tag with the lowest ID represents each term; tags with a null `term_id` are excluded.

### Validation errors

If `page` or `per_page` is supplied with an empty or invalid value, the API returns HTTP `422` with validation errors.
For example, `page=0`, `page=1.5`, `per_page=101`, and `per_page=` are invalid. Omit both pagination parameters to keep
the unpaginated response; passing empty values does not disable pagination.

Existing search errors, such as a missing or unsupported `type`, continue to return HTTP `400` when the pagination
parameters are valid or absent.
